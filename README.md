# 操作系统实验二 同步机制及应用编程实现与比较

王旭升 · 24281204 · 保密2401  
对应实验指导书“实验课题5”，仓库名中的 lab2 为课程实验编号。

C++17 与 POSIX pthread 实现银行双账户转账的无同步、Peterson、操作系统互斥锁三种方案。

## 编译与运行

Linux（安装 g++、make、Python 3）或 macOS（Command Line Tools）：

```bash
make
./bank_transfer all 1000000 5
./bank_transfer all 5000000 5
./bank_transfer none 1000000 3 --amplify
bash scripts/run_all.sh local
```

`loops` 为每个线程的循环上限；同步模式应完成 `2*loops` 次转账。无同步模式检测到破坏守恒的观察值即提前退出，故不能用其提前结束耗时与同步模式作等量性能比较。`--amplify` 只在无同步模式插入 yield 来放大交错，结果单独保存。

## 实现要点

- 两个全局整型账户初值为 0；两个线程使用相同工作函数。每次将 1..100 的随机整数从账户2转入账户1。
- 使用独立 xorshift32 随机流，种子为 24281204 和 24293549；随机数生成放在临界区外。
- C++ 中对普通共享 int 的并发读写会产生未定义行为，因此账户使用 `std::atomic<int>` 的 relaxed 单次读写。四步事务仍没有原子性；none 模式没有事务锁，能观察到逻辑竞态。此实现是指导书伪代码的语言内存模型修订。
- Peterson 的 flag/turn 全部使用 seq_cst 原子操作，避免编译器/CPU 重排破坏算法。仅支持两个固定线程，等待时忙等。
- mutex 使用 `pthread_mutex_init/lock/unlock/destroy`。锁覆盖读取、更新、守恒检查。
- 使用 32 位以上 int，最多 2×5000000 次、每次至多100，总量至多10亿，未超过32位有符号整数范围。
- 无同步模式中的 `observed_sum` 可反映另一线程转账中途的状态；即使 join 后 `final_sum=0`，也不能说明执行过程中正确。同步模式还通过离线重放随机流检查最终余额，排除成对丢失更新。

## 输出与验证

CSV 注释包含姓名、学号、操作系统、架构、编译器。列包含各线程完成次数、最终余额、最终和、异常观察值、完成标志、墙钟毫秒、进程 CPU 毫秒及吞吐量。

计时从两个线程就绪后的共同起点开始，到 join 完成结束；包括末尾 join 开销，不包括线程创建和控制台输出。每种规模重复5轮，交替执行顺序；比较应采用中位数并保留范围。CPU时间是进程各线程累计，可能大于墙钟时间。

`python3 scripts/verify_results.py results/native_1m.csv results/native_5m.csv` 会独立重放随机数序列验证同步余额、次数和守恒。`results/native_*` 为本机 macOS 实测，不能当作 Linux 性能数据。Linux 工作流运行结果见 Actions 下载产物。

## 本机实测摘要

两种规模各5轮；仅比较完成全部工作且验证通过的同步模式。

| 每线程次数 | 方案 | 墙钟中位数 ms | 范围 ms | 进程 CPU 中位数 ms |
| --- | --- | ---: | ---: | ---: |
| 1000000 | Peterson | 510.545 | 482.985–536.082 | 1020.092 |
| 1000000 | pthread mutex | 32.897 | 31.413–33.263 | 51.926 |
| 5000000 | Peterson | 2546.903 | 2512.222–2567.079 | 5091.700 |
| 5000000 | pthread mutex | 162.558 | 159.141–165.679 | 255.673 |

无同步自然交错测试10轮均检测到非零中途观察值；单独 yield 测试3轮中1轮检测到异常。无异常并不证明无锁执行正确。
